# T1136.001 Create a new user in a command prompt

## Att&ck description
"Adversaries may create a local account to maintain access to victim systems. Local accounts are those configured by an organization for use by users, remote support, services, or for administration on a single system or service."

## Triaging steps
Check if the account name/creation is expected (data.win.eventdata.commandLine). Is there a scheduled admin task? IT service? Or is it a random and unusual username?

Check what process created it. (data.win.eventdata.originalFileName), and take note of the folder the process was invoked in (data.win.eventdata.currentDirectory) Look for unusual staging folders like TEMP. 

Check what account was used to create the user, (data.win.eventdata.user). If a elevated or privleged account was used, treat the incident as potential credential compromise and follow admin account steps outlined below.

Check if created account has been used to login yet. Search for logon events (EID 4624) under the newly created account name.

Check if account was added to a privleged group.


## Containment guide
Disable the account immediately. `Disable-LocalUser -Name "<created-account-name>"`

But don't delete the account yet, preserve for forensic review.

## For potential compromise of admin account
First, check for any active sessions `query session`, If there is evidence of an active session, isolate WS01 from the network. 

Reset compromised account password immediately `Set-ADAccountPassword -Identity "<compromised-account-name>" -Reset -NewPassword (ConvertTo-SecureString "<new-secure-password>" -AsPlainText -Force`

Password reset doesn't revoke existing kerberos tickets, force immediate invalidation by disabling and re-enabling the account.
  1. `Disable-ADAccount -Identity "<account-name>"`
  2. `Enable-ADAccount -Identity "<account-name>"`
